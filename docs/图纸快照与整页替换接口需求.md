# 当前图纸审阅与整页更新：开发对接约定

> **0.2.4 本版停用此方案，仅留作后续参考。** 当前实现不读快照、不审阅人工改图；以 [手动更新与清空图页接口](手动更新与清空图页接口.md) 为准。

状态：接口提案，**尚未实现完整链路**。0.2.3 首轮绘图不依赖 GetItems；审阅人工修改后的实际图纸，需要 KiCad 宿主、插件和 AI 服务共同接入本文能力。现有反馈 API 不接受下文新增的快照字段，不能直接给旧接口增加任意 JSON 字段。

## 产品行为

- 主窗口默认 500×740，可缩到较窄的辅助窗口；设计、任务、连接用顶部页签切换。技术协议与文字共同提交一个设计任务。
- 首轮只识别目标图纸及已有坐标约定，再创建符号/导线，不读取原有图纸对象。建议选择独立 AI 图页；此模式不能发现已有内容或保证避开它。
- 后续用户可能移动、旋转、换型号、删增器件、改连线。审阅必须读取这些实际变化，不能拿服务端旧 Graph IR 假装当前图。
- **先读图并保存可恢复快照 → 后端审阅或修订 → 生成可交付的新 Graph IR → 再事务替换指定图页。** 咨询只返回报告，不清图；快照失败、模型失败或结果不完整都保留原图。
- “整页”指用户选定的当前 AI 原理图页，包含人工新增/替换的对象，不指清空整个多页工程。

## 三方职责

| 位置 | 要做什么 |
| --- | --- |
| KiCad 宿主 | 导出真实图页、连接与原生备份；提供按图页事务替换和状态查询 |
| Python 插件 | 保存快照，关联 UUID 与原 Graph IR 节点，归一化数据、计算人工改动，上传后端；解析新 Graph IR 并生成待绘制对象 |
| AI 服务 | 接受画布快照/差异及原设计基准；核对型号/端口事实；审阅或修订设计；返回报告和必要时的新 Graph IR |

不要求 KiCad 理解 LLM 或 Graph IR。图布局、Graph IR 到符号/导线的转换仍可在 Python 中完成。

## 能力一：读取并保存当前图页快照

建议逻辑名 `ExportSchematicSnapshot`，不是宣称当前宿主已有此命令。可由完整的 GetItems、连接信息及原生序列化组合实现；只返回部分符号/导线的 GetItems 不能冒充完整快照。

输入：明确的工程/文档 ID、sheet_path，以及可选选中 UUID。返回至少包括：

| 字段 | 内容 |
| --- | --- |
| snapshot_id / snapshot_schema | 快照唯一 ID 与版本，如 `rf-eda-schematic-snapshot/v1` |
| document_id / sheet_path / document_revision | 精确目标与读取时版本；读取应保持一致，不能混合多个时刻的数据 |
| units_per_mm / coordinate_unit | 位置、尺寸和网格的尺度约定 |
| symbols | 实际 UUID、库 ID、位号、值、字段/参数、单元、位置、角度、引脚号/名称及实际位置 |
| nets / wires / junctions | 引脚连接分组、导线端点、交点与 UUID；不能仅靠显示坐标推断所有电气连接 |
| labels / power / buses / sheets | 标签、隐式电源、总线及层级引用；不支持的类型须列为不完整，不能静默遗漏 |
| native_backup / sha256 | 可无损恢复的原生备份与摘要；可只留在客户端，不必全部发给 LLM |
| completeness / unsupported_types | 是否覆盖当前图页全部内容；不完整时只能有限分析，不允许据此清空原图 |

只有 JSON 中的器件坐标，不能保证恢复图纸的所有属性、图形、库内容及层级关系。整页删除前必须有原生恢复依据。

## 能力二：插件归一化与后端审阅

插件输出独立的 `CanvasSnapshot` 与 `CanvasDelta`，不覆盖服务端原 Graph IR：

1. 保留 UUID → 原 node_id/edge_id 映射；换器件、删除重建后 UUID 可能变化，匹配不明确必须标记待确认。
2. 归一化型号、参数、单元、真实引脚和网络。人工新器件还需关联符号库/知识库事实，不能从显示名称猜完整器件含义。
3. 分开记录位置/方向变化、型号/参数变化、节点和连线增删。坐标变化不等于电气结构变化，但移动后仍须核对是否断线。
4. 提交原 job_id、base_revision、base_graph_hash、instruction、snapshot_id/摘要、归一化快照/差异及可选选择范围。
5. 后端必须提供显式接收快照的协议；当前的 `client_graph_dirty` 拒绝策略、快照验证及保存方式需要相应扩展。未检测不能填成已确认无修改。

LLM 输入应使用归一化摘要、实际连接和变化清单，结合服务端保存的需求/架构/器件事实；不是把原生文件 Base64 直接塞给模型。无法从当前图恢复的原设计意图要继续引用原设计状态或要求用户说明。

“器件放得对不对”要区分：

- 排版：位置、方向、遮挡、可读性和连线走向，必要时补图像；不一定修改电气 Graph IR。
- 型号/连接：实际型号、端口、参数及网络，结合设计需求审阅，必要时产生新版 Graph IR。
- RF 实际性能：还需要真实模型和计算/仿真，不能凭图纸 JSON 宣称验证通过。

审阅或澄清只产生反馈，不生成新图时不允许清空。只有明确修订成功并形成完整新图，才进入替换。

## 能力三：备份后事务替换指定图页

建议逻辑名 `ReplaceSchematicContent`，同样是待实现契约。插件可先把新 Graph IR 解析成符号和导线，再提交给此接口。

输入至少包含：`operation_id`、`document_id`、`sheet_path`、`expected_document_revision`、`snapshot_id/hash`、已保存备份凭据、完整新对象列表，以及 `scope=current_sheet_all_items`。

宿主应做到：

1. 比较文档身份及版本；用户在等待 AI 时又改图，返回冲突，不能覆盖后来修改。
2. 确认可恢复备份已保存；在同一事务内删除指定图页所有旧对象、创建新符号/导线。
3. 任一对象失败则整次回滚；全部成功才提交，返回实际 UUID 映射与新版本。
4. 同一 operation_id 防重；响应丢失可查询提交状态，不盲目再次清空。
5. 提供撤销/恢复到原生备份的路径。`committed / rolled_back / unknown` 必须明确。

现有 `BeginCommit + DeleteItems + CreateItems + EndCommit` 只有在能够获得完整对象集合、提供一致性检查并保证回滚时，才能组合实现整页替换。**仅有上一轮插件 UUID，无法删除人工新增或替换后出现的新 UUID，不能实现用户要求的清空整页。**

## 最小验收

首轮宿主拒绝 GetItems 时仍可创建；审图导出失败时旧图不变；移位、换型号、增删对象及改网均可识别；咨询不清图；失败回滚可恢复人工修改；只清指定页；等待期间再编辑会冲突；重复请求/丢失响应不造成重复删除或重复绘图。
