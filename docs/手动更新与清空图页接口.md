# 手动更新原理图与现有接口绑定

适用插件 0.2.6。首轮和反馈完成后保存设计结果；用户点击 **更新原理图**，确认后替换当前图页并创建符号与导线。没有待应用结果时，主操作为 **清空当前图页**。本文面向开发维护者，描述现有通信及事务约定。

## 用户流程

1. Word / 文字 / Word＋文字生成 → 下载并保存完整 Graph IR，不操作 KiCad。
2. 查看“设计指标要求”表格、HTML 报告，或直接继续反馈，不要求先绘图。
3. 反馈使用后端的当前成功版本、需求及设计状态，生成新版 Graph IR；不自动刷新画布。
4. 用户点击更新原理图，确认清空当前活动图页；插件预先检查新图和符号，开启事务，清空整页，创建新对象，全部成功后提交。
5. 清空、创建任一步失败则撤销整个事务；结果留在客户端，可在接口修复后再次应用，不必重跑 AI。提交响应未知时禁止自动重复清空，用户处理旧操作后可显式允许再更新。

清空范围为指定原理图页上的全部旧设计对象，包括人工新增对象；不删除工程、图页本身或其他图页文件。不能只根据上次插件 UUID 删除一部分对象，却声称整页已清空。

## 现有 KiCad 宿主接口

现有清空与更新接口由定制 KiCad 宿主提供。插件继续使用 `GetActiveSchematicContext`、`SearchSymbolLibrary`、`GetSymbolLibraryDefinition`、`CreateItems`、`BeginCommit/EndCommit` 和 `ClearSchematicPage`，本次不增加宿主命令。当前反馈使用 `backend_only`；没有启用画布快照或本地修改合并。

保留现有的两条清空调用路径：

- **单命令清空**：调用现有 `kiapi.schematic.commands.ClearSchematicPage`，与下列 Protobuf 和事务约定绑定。
- **已有接口回退**：完整 `GetItems` 返回当前页全部对象，插件只取其 UUID 再调用 `DeleteItems`。这些数据仅用于删除，不形成快照，不发送给后端/LLM。未知或缺失 UUID 时取消清空，避免旧图残留。

若现有构建两条都不支持，插件会返回 `KICAD_CLEAR_UNSUPPORTED` 并保留原图，不能仅靠 Python ZIP 给 KiCad 增加 C++ 处理器。

### ClearSchematicPage 协议

文件：[schematic_clear.proto](../plugins/protocol/schematic/schematic_clear.proto)。与宿主原有 `common/types/base_types.proto` 一起编译；Any 中的类型全名必须相同。

```protobuf
package kiapi.schematic.commands;
message ClearSchematicPage {
  kiapi.common.types.DocumentSpecifier document = 1;
  string request_id = 2;
}
message ClearSchematicPageResponse {
  bool success = 1;
  uint32 deleted_count = 2;
  string message = 3;
}
```

处理器必须：

1. 验证目标文档为请求指定图页，并确认当前客户端已有活动 `BeginCommit`。
2. 将该图页全部旧对象的删除加入同一事务，不能自行保存或提交，不影响其他图页。
3. `success=true` 只能表示清空操作已全部加入事务；即使原图为空也返回 true 和 0。失败必须返回失败，不报假成功。
4. 后续 `CreateItems` 和清空属于同一事务；`EndCommit(commit=false)` 必须能够恢复被删对象，`commit=true` 才整体提交。支持一次用户撤销。
5. 原有封装 `ApiResponse.status` 的鉴权、错误和类型约定不变。未注册命令应返回 `AS_UNHANDLED`，插件才能尝试已有接口回退。

### 客户端调用顺序

```text
用户确认更新
→ 后端当前成功图 / 新图完整性检查
→ 当前目标图页、坐标及符号定义
→ 本地保存绘图操作日志（不是图纸快照）
→ BeginCommit
→ ClearSchematicPage；AS_UNHANDLED 时 GetItems + DeleteItems
→ CreateItems（符号）
→ CreateItems（导线）
→ EndCommit(commit=true)
```

任一失败进入 `EndCommit(commit=false)`。回滚响应未知时保留“待确认”状态，不假报原图已恢复。不要将 ClearSchematicPage 作为事务外的探测命令调用。

## AI 服务协议变化

`GET /api/v1/capabilities` 的 `revision.canvas_policies` 声明支持 `backend_only`。

`POST /api/v1/jobs/{job_id}/revisions` 使用：

```json
{
  "request_id": "revision-唯一标识",
  "base_revision": 1,
  "base_graph_hash": "服务端 revision-state 返回的64位摘要",
  "instruction": "增加一级滤波器",
  "selection": {"node_ids": [], "edge_ids": []},
  "canvas_policy": "backend_only"
}
```

本模式省略 `client_graph_dirty`，避免把未检查画布伪装成已确认无修改。基准版本、hash、防重复、单个 pending 仍检查，但都属于服务端设计状态。旧客户端不传 canvas_policy 时仍保持原有 verify_local/dirty 约定。部署时使用支持此协议的 AI 服务。

## 本地记录与指标表

- 清空日志：仅清运行日志。
- 清空对话：持久清除当前对话，保留任务和画布。
- 清除任务记录：清除本会话的对话、输入、任务/版本列表；不删除服务端任务文件、不操作原理图。保留绘图收据，待确认请求或绘图不能静默丢弃。
- 新设计：清空当前对话和输入，开始独立后端设计；旧任务索引仍在版本记录，可另行清除。
- 设计指标要求：仍读取 `/requirements` JSON，客户端显示表格，列为要求编号、指标名称、要求值、单位、比较、来源、采用状态、依据。支持筛选、原文详情及复制表格；零值、待定值、假设明确区分。

验收至少覆盖：生成/恢复/反馈零 IPC；首轮与反馈共享手动更新；清空包含人工新增对象；失败整体回滚；清空能力缺失时原图保留；未知结果不自动重放；记录删除后重开不恢复；指标表与后端原始值、来源一致。
